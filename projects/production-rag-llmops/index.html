Production RAG / LLMOps

RAG, prompt versions, citations, groundedness, provider boundary

Markdown corpus → overlapping chunks → TF-IDF + BM25 fused with RRF → versioned prompt → generator. The default generator is extractive so CI does not need vendor keys. The API returns citations, a groundedness flag, token estimates, and a cache hit marker.

Capability
GenAI / RAG: chunking, hybrid retrieval, versioned prompts, citations, and a swappable generator.
Evaluation
Groundedness is a token-subset check against assembled context. hallucination_flag is the inverse when citations exist.
Deployment
FastAPI /v1/ask. Default provider is extractive. HTTP adapter is env-configured and not invoked in CI.
Monitoring
Whitespace token estimates, cache-hit marker, retrieval count, request ids. Not billed telemetry.
Failures
Empty index is not ready. Unknown questions return a closed answer. Blocklisted input is 400. Unknown prompt versions fail closed.

Problem

Dumping a PDF into an embedding API and printing the model’s paragraph is not an operable retrieval system. Retrieval, generation, evaluation, and safety have to be separate so you can tell which one broke.

Retrieval

HybridIndex stores TF-IDF vectors and BM25 statistics over the same chunks. Reciprocal rank fusion is justified because operational text mixes exact tokens (hard decline) with paraphrases. top_k is a setting, not a magic number in the route.

Generation

Prompt templates live in prompts.py with versions (grounded-v1, short-v1). LLMProvider is a Protocol: ExtractiveProvider (default, quotes the top chunk with [doc_id]) and HttpLLMProvider (needs RAG_LLM_URL and RAG_LLM_API_KEY). The HTTP class builds the request contract and refuses to call a network in this repository.

Evaluation

grounded is a token-subset check against assembled context. hallucination_flag is the inverse when citations exist. These are CI heuristics, not published quality numbers.

Observability and safety

Each answer records tokens_in / tokens_out (whitespace estimates). A small blocklist rejects obvious injection phrases. A sliding-window limiter sits on /v1/ask. Identical questions hit an in-memory cache.

What I would improve next

A corpus-hash persistent index, actual httpx calls behind HttpLLMProvider with timeouts and cost counters (not enabled here), and a labeled recall@k set instead of term overlap.

Engineering decisions

Why not LangChain + a hosted vector DB?
The retrieval math is the thing to get right. A framework would hide BM25 vs cosine vs fusion. A hosted index would make CI need credentials.
Why an extractive generator?
Fluent answers hide retrieval bugs. Tests should fail when the wrong chunk is first, not when a billed model paraphrases around it.
