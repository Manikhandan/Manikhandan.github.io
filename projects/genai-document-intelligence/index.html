GenAI Document Intelligence

Document AI, schema validation, human-in-the-loop, async reliability

Ingest document text, classify, extract fields against a schema, score confidence, and either complete, wait for a human, or retry into a dead-letter queue. The LLM/OCR boundary is an extractor interface; the default implementation is local and deterministic so CI needs no vendor keys.

Capability
GenAI document application: ingest, classify, structured extract, confidence, human review, persist, API.
Evaluation
Pydantic schema on invoice fields. Low confidence or unknown class goes to needs_review instead of completing.
Deployment
Async job API. Processor is a drain seam; a worker Deployment is the production split.
Monitoring
Per-job audit events on every state transition, including dead-letter.
Failures
Duplicate submit is idempotent. Schema failures retry then dead-letter. Review in the wrong state is 409. No OCR in this default.

Problem

Document work does not fit a scoring SLO. Extraction fails in messy ways and sometimes needs a reviewer. A synchronous handler either times out or pretends the document is simpler than it is.

Why asynchronous

The client stores job_id and polls /v1/jobs/{id}. The processor is a function over that id. A production split is a worker Deployment; /v1/worker/drain is the seam. Tests drain in-process so they stay deterministic.

Job lifecycle

queued → running → completed | needs_review | queued (retry) → dead_letter. Audit events are appended on every transition. Blobs sit next to the JSON store.

Extraction and validation

DocumentExtractor is a Protocol. LocalExtractor is lexical classify plus regex fields (used in CI). RemoteExtractor is the OCR/LLM boundary and raises NotImplementedError — this repository does not run OCR. InvoiceFields is a Pydantic schema; missing INV- ids fail closed.

Human review

Low confidence or classification=unknown goes to needs_review. POST /v1/jobs/{id}/review with approve (optional field overlay) or reject (dead-letter).

Security

DOCINTEL_API_KEY is empty in .env.example so local tests run; any shared environment should set it. Blobs are local files, not a multi-tenant document store.

What I would improve next

Object storage for blobs, a queue with leases, and an implementation of RemoteExtractor that actually calls OCR or an LLM — still behind the same Protocol.

Engineering decisions

Why not extract in the request handler?
Because retries, review, and dead-letter need a job id that outlives the HTTP socket. Idempotency is cheap when the unit of work is a job.
Why regex instead of an LLM?
The interesting part is the state machine and the schema. An LLM can sit behind extract_fields later without changing JobStore.
