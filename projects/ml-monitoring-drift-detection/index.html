AI / ML reliability · Data quality, drift, accuracy, serving health

ML Monitoring and Drift Detection

Data drift, prediction drift, performance degradation, operational action

Ingest prediction events, compare a window to a reference snapshot, and emit a report: data PSI, prediction PSI, optional accuracy, error rate, latency, and alerts that carry a severity and an action — including a retrain_signal that does not silently mutate Production.

Capability
AI/ML reliability: data quality, data drift, prediction drift, accuracy, error rate, inference health.
Evaluation
PSI and KS against a reference snapshot. Accuracy only when labels are present — no invented ground truth.
Deployment
FastAPI ingest + /v1/report. Prometheus text on /metrics. Non-root container.
Monitoring
Named alerts with severity and an action string. retrain_signal is a flag, not a fit().
Failures
Windows under 20 events report PSI 0. Missing labels leave accuracy null. Error-rate pages on-call, not retrain.

Problem

Scraping one Evidently HTML file is not a monitoring platform. Data drift, prediction drift, and accuracy drops are different questions and imply different next steps.

Categories

System: error rate, latency, throughput. Data quality: null_rate. Data drift: mean PSI across features. Prediction drift: PSI and KS on scores. Performance: accuracy when labels are present (concept-adjacent; without labels the service will not pretend).

Alert routing

watch / ticket / page plus an action string. data_drift at psi_alert → retrain_signal. prediction_drift → compare histograms. accuracy below floor → retrain_signal. error_rate → page_oncall (serving problem until proven otherwise).

What happens after an alert

retrain_signal is a flag on /v1/report. A pipeline can subscribe to it. This service does not fit a new model. That split is the point.

What I would improve next

Freeze the real training matrix as reference instead of a first-boot snapshot, and export gauges on a schedule rather than computing on scrape.

Engineering decisions

Why not auto-retrain?
PSI false-alerts on small windows. Training is a control-plane action with gates. Monitoring should not own that button.
Why separate data drift from prediction drift?
Features can move while scores stay put (or the reverse). Those are different investigations.
