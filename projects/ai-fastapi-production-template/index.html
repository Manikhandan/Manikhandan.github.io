AI FastAPI Production Starter

AI APIs, validation, auth, rate limits, provider swap

FastAPI routes call an InferenceService, which calls a provider Protocol. EchoProvider is the default so the template runs without a model file. Auth is an optional API key. Rate limiting is a sliding window. Request ids and JSON logs are on every response. This is an application skeleton, not an infrastructure demo.

Capability
AI application skeleton: routes → InferenceService → provider Protocol, not infrastructure around a model.
Evaluation
Contract tests for auth, validation, retries, rate limit, and structured errors. EchoProvider is deterministic.
Deployment
Non-root image. Kubernetes pulls AI_API_KEY from a Secret. Empty key is for local tests.
Monitoring
JSON logs and x-request-id on every response. /health vs /ready (provider name present).
Failures
401 without a key, 422 on empty text, 429 on the limiter, 500 as {error: internal} when the provider dies.

Problem

Inference code often lands in the route. Then there is no place for retries, a second provider, or tests that do not boot the whole framework.

Layers

api (main.py) → services/inference.py → providers/* . domain/models.py holds PredictIn/Out. config is pydantic-settings with an AI_ prefix. infra holds logging, auth, and the limiter.

Runtime behaviour

/health is liveness. /ready reports the provider name. /v1/predict validates text, checks the API key if set, and retries the provider. Unhandled exceptions become {error: internal}.

Deployment

Non-root Docker image. Kubernetes manifest pulls AI_API_KEY from a Secret. Empty key in .env.example is for local tests — not a default to ship.

What I would improve next

OpenTelemetry traces, and an httpx provider with explicit timeouts instead of only retries around a sync call.

Engineering decisions

Why a Protocol for providers?
So a model file or a remote HTTP client can replace EchoProvider without touching the route. Tests construct EchoProvider directly.
Why is auth off when the key is empty?
pytest and first clone should work. A shared environment must set AI_API_KEY. The Kubernetes manifest already expects a Secret.
