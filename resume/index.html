Selected systems

  • Production ML Deployment Platform. Tabular classification from data validation through feature scaling, training, holdout evaluation, a quality gate, an immutable registry, Staging → Production promotion, FastAPI inference, and a PSI window on live features.
  • End-to-End MLOps Pipeline. The ML development path (ingest, validate, features, train, evaluate) is a different graph from the MLOps automation path (register, promote, package a serving bundle). A monitor stage can raise a retrain trigger when PSI or error rate crosses a threshold.
  • Production RAG / LLMOps. Markdown corpus → overlapping chunks → TF-IDF + BM25 fused with RRF → versioned prompt → generator. The default generator is extractive so CI does not need vendor keys. The API returns citations, a groundedness flag, token estimates, and a cache hit marker.
  • GenAI Document Intelligence. Ingest document text, classify, extract fields against a schema, score confidence, and either complete, wait for a human, or retry into a dead-letter queue. The LLM/OCR boundary is an extractor interface; the default implementation is local and deterministic so CI needs no vendor keys.
  • ML Monitoring and Drift Detection. Ingest prediction events, compare a window to a reference snapshot, and emit a report: data PSI, prediction PSI, optional accuracy, error rate, latency, and alerts that carry a severity and an action — including a retrain_signal that does not silently mutate Production.
  • AI FastAPI Production Starter. FastAPI routes call an InferenceService, which calls a provider Protocol. EchoProvider is the default so the template runs without a model file. Auth is an optional API key. Rate limiting is a sliding window. Request ids and JSON logs are on every response. This is an application skeleton, not an infrastructure demo.
