ML engineering + serving

Production ML Deployment Platform

Classification, evaluation, registry, inference

Supervised ML, quality gates, versioned serving, drift window

Tabular classification from data validation through feature scaling, training, holdout evaluation, a quality gate, an immutable registry, Staging → Production promotion, FastAPI inference, and a PSI window on live features.

A fitted sklearn object is not a production path. The missing pieces are evaluation you can fail, an immutable version, an explicit promotion step, a replica that can refuse traffic, and a way to notice incoming features no longer match the training reference.

ML development lifecycle

End-to-End MLOps Pipeline

From data through retrain — two graphs, not one script

Feature engineering, evaluation gates, experiment runs, retrain trigger

The ML development path (ingest, validate, features, train, evaluate) is a different graph from the MLOps automation path (register, promote, package a serving bundle). A monitor stage can raise a retrain trigger when PSI or error rate crosses a threshold.

One script that trains and copies a file into a serving folder hides the moment a model becomes the thing you actually run. Training is a batch job with gates. Deployment is a freeze of a version.

GenAI / LLM engineering

Production RAG / LLMOps

Retrieval, prompts, generation, evaluation

RAG, prompt versions, citations, groundedness, provider boundary

Markdown corpus → overlapping chunks → TF-IDF + BM25 fused with RRF → versioned prompt → generator. The default generator is extractive so CI does not need vendor keys. The API returns citations, a groundedness flag, token estimates, and a cache hit marker.

Dumping a PDF into an embedding API and printing the model’s paragraph is not an operable retrieval system. Retrieval, generation, evaluation, and safety have to be separate so you can tell which one broke.

GenAI application

GenAI Document Intelligence

Structured extraction with review and a job API

Document AI, schema validation, human-in-the-loop, async reliability

Ingest document text, classify, extract fields against a schema, score confidence, and either complete, wait for a human, or retry into a dead-letter queue. The LLM/OCR boundary is an extractor interface; the default implementation is local and deterministic so CI needs no vendor keys.

Document work does not fit a scoring SLO. Extraction fails in messy ways and sometimes needs a reviewer. A synchronous handler either times out or pretends the document is simpler than it is.

AI / ML reliability

ML Monitoring and Drift Detection

Data quality, drift, accuracy, serving health

Data drift, prediction drift, performance degradation, operational action

Ingest prediction events, compare a window to a reference snapshot, and emit a report: data PSI, prediction PSI, optional accuracy, error rate, latency, and alerts that carry a severity and an action — including a retrain_signal that does not silently mutate Production.

Scraping one Evidently HTML file is not a monitoring platform. Data drift, prediction drift, and accuracy drops are different questions and imply different next steps.

AI application engineering

AI FastAPI Production Starter

A cloneable inference API with a provider boundary

AI APIs, validation, auth, rate limits, provider swap

FastAPI routes call an InferenceService, which calls a provider Protocol. EchoProvider is the default so the template runs without a model file. Auth is an optional API key. Rate limiting is a sliding window. Request ids and JSON logs are on every response. This is an application skeleton, not an infrastructure demo.

Inference code often lands in the route. Then there is no place for retries, a second provider, or tests that do not boot the whole framework.
